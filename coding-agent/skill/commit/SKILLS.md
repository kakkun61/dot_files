# commit

現在の作業ツリーの変更を **1 コミット**にする。汎用。特定のメッセージ書式を持ち込まず、
**そのリポジトリの `git log` に現れる慣習に合わせる**こと。

## 手順

### 1. 変更を把握する
- `git status` と `git --no-pager diff`（`git --no-pager diff --staged` も）で、何が入るかを確認する。
- **`git add -A` / `git add .` は使わない**。意図した追跡ファイルだけを明示的に `git add` する。
- `.gitignore` 済みの生成物は対象外。
- 無関係な変更が混ざっていたら、どれを含めるかユーザーに確認する。

### 2. コードコメントを整理する
- 今回の作業で、変更したコードに「なぜこうしたか」を説明するコメントを足していたら、
  **それを削除し、理由はコミットメッセージ本文へ移す**。
- 周囲のスタイルに沿った通常のコメントはそのまま残す（削除するのは今回の変更理由の注釈だけ）。
- 生成ファイルを介すプロジェクトでは、コメント削除後に生成し直す。すでにデプロイ済みなら
  再適用する（手順が不明ならユーザーに聞く）。

### 3. メッセージのスタイルを合わせる
- `git log --oneline -20` と直近数件の本文（`git log -3`）を読み、そのリポジトリの慣習に合わせる:
  - 件名の書式（プレフィックス・タグ・言語・文体・長さ）
  - 本文の有無と粒度
- 本文には**「なぜ」「背景」**を書く。「何をしたか」は diff で分かるので繰り返さない。
- 迷ったら直近のコミットに最も近い形にする。

### 4. コミットする
- メッセージはスクラッチ用の一時ファイルに書き、`-F <その一時ファイル>` で渡す
  （複数行・日本語の文字化け／取り違え防止。`-m` を並べない）。
- 実行:
  ```sh
  git commit --no-gpg-sign --author="Claude <noreply@anthropic.com>" -F <その一時ファイル>
  ```
  - **author は `Claude <noreply@anthropic.com>`**。
  - **`--no-gpg-sign` を既定で付ける**。署名設定（`commit.gpgsign=true`）があっても、
    非対話シェルでは pinentry がタイムアウトして署名に失敗するため。
    ユーザーが「署名して」と明示した場合のみ `--no-gpg-sign` を外す
    （その場合は失敗しうる旨を伝え、失敗したらユーザーにターミナルでの実行を促す）。
- メッセージ本文の末尾に、空行を 1 つ挟んで co-author トレーラーを入れる:
  ```
  Co-Authored-By: <git config user.name> <git config user.email>
  ```
  値は `git config user.name` / `git config user.email` から取る（＝そのリポジトリに設定された
  git ユーザー＝コミットを指示した本人）。

### 5. 結果を見せる
```sh
git --no-pager log -1 --format='%h%nauthor:    %an <%ae>%ncommitter: %cn <%ce>%nsigned:    %G?%n%n%B'
```
author が Claude、committer / co-author が設定ユーザー、署名なし（`N`）になっていることを確認できるようにする。

## しないこと
- `git push`（別途、明示指示があるときだけ）
- 無関係な複数の変更を 1 コミットに混ぜる
- `--no-verify` によるフック回避
- 既定ブランチで作業中でも、このリポジトリの慣習が「直接コミット」ならそれに従う
  （履歴が一貫して直接コミットなら branch を切らない）
